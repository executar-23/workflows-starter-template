# Redação Técnica

## Quando usar

Use quando o entregável for:

- relatório;
- artigo técnico;
- análise;
- documento acadêmico;
- síntese estruturada de pesquisa;
- apresentação de dados externos em Markdown.

## Princípios

- Organize da conclusão geral para os detalhes.
- Apresente uma etapa lógica por vez.
- Expresse uma proposição principal por frase.
- Não misture definição, fato, julgamento, exemplo, exceção e recomendação na mesma sentença.
- Defina termos especializados e expanda abreviações.
- Não presuma conhecimento não declarado.
- Use linguagem direta, concisa e densa em informação.
- Prefira explicações literais a metáforas.

## Estrutura

Use GitHub-flavored Markdown por padrão.

Prefira parágrafos completos e tabelas quando elas melhorarem comparação ou organização.

Use tabelas Markdown com pipes.

Evite HTML para tabelas.

## Referências

Inclua uma seção `References` no final quando houver fontes externas.

Use IDs numéricos consistentes:

```markdown
[1]: https://example.com "Título descritivo da fonte"
```

Cite no texto como `[1]`.

Para múltiplas fontes, use `[1] [2]`.

Não use aliases como `r1`, URLs soltas ou referências aninhadas.

## Citações

Use blockquotes para trechos completos citados e identifique claramente a fonte.

## Visualizações

Quando gráficos ou imagens forem necessários para sustentar a análise:

1. gere a visualização como arquivo de imagem;
2. insira-a no documento usando sintaxe Markdown.

## Reescrita final

A versão entregue deve ser uma reescrita final completa.

Notas intermediárias não podem ser o único resultado.

Ao entregar arquivos importantes, mantenha a mensagem de acompanhamento curta e direcione o usuário ao arquivo.
